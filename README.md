# CovLedger

**Python test evidence and code-quality signals for coding agents.**

CovLedger is a deliberately small Python-only experiment inspired by Supercov's strongest idea: turn test execution into durable, queryable evidence that an agent can inspect one gap at a time.

This MVP is intentionally narrow:

- Python 3.12+
- pytest only
- `coverage.py` as the first evidence backend
- line + branch coverage
- immutable local run directories
- source snapshots for every measured file
- run-to-run diffs
- deterministic AST quality facts
- optional semantic quality judgments through PyJev

It does **not** claim MC/DC, assertion coverage, arbitrary test-runner support, or a custom `sys.monitoring` collector yet.

## Development

CovLedger uses a flat package layout: there is no `src/` directory.

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
pytest
```

Versioning is dynamic through `setuptools-scm`. Git tags are the source of truth:

```bash
git tag v0.1.0
python -m build
```

`covledger/_version.py` is generated by `setuptools-scm` and is intentionally not committed.

## First run

Run the real pytest suite through CovLedger:

```bash
covledger run -- pytest -q
```

Then inspect the evidence without rerunning tests:

```bash
covledger runs
covledger runs latest
covledger runs latest gaps
covledger runs latest file path/to/module.py
```

Compare two immutable runs:

```bash
covledger diff <older-run-id> <newer-run-id>
```

## Quality

Deterministic Python facts require no API key:

```bash
covledger quality .
```

Add semantic judgments with PyJev:

```bash
covledger quality . --semantic
```

The semantic boundary is explicit: Python chooses function boundaries and computes exact facts; PyJev judges only the fuzzy properties defined in `covledger/quality_rules.toml`.

The bundled MVP semantic rules are:

- hidden side effect
- too many conceptual jobs
- surprising mutation
- implicit global/process state
- hidden I/O
- policy/mechanism mixing
- ambiguous error contract
- misleading name

PyJev authentication follows PyJev's own configuration and credential handling.

## First run and storage layout

Initialize the canonical Ledgercore project before collecting evidence:

```bash
covledger init
covledger run -- pytest -q
covledger runs latest
covledger next
```

CovLedger keeps project identity and tool configuration in the checkout, but stores generated evidence outside Git by default:

```text
project checkout
└── .ledger/
    ├── ledger.toml
    └── covledger/
        ├── .ledger-project.toml
        └── config.toml

sibling store
└── ../ledger/
    ├── .ledger-store.toml
    └── covledger/
        └── <project-uuid>/
            └── runs/
                └── <uuidv7>/
```

The CovLedger registration in `.ledger/ledger.toml` controls the external root. Ledgercore namespaces persistent runs by tool name and project UUID, so multiple repositories can safely share `../ledger`. Semantic cache data uses Ledgercore's platform cache and is also outside the checkout.

Published run directories use the canonical UUIDv7 run ID exactly. Published `run.json` files are immutable, and `latest` is only a selector. CovLedger does not create or use `.covledger` as active storage.
## Risk assessment workflow

After a run, CovLedger builds an immutable `assessment.json` containing deterministic hotspot scores, function and finding IDs, coverage gaps, and repository context:

```bash
covledger overview
covledger findings --min-score 70
covledger inspect F-xxxxxxxxxx
covledger inspect Q-xxxxxxxxxx
covledger inspect G-xxxxxxxxxx
covledger next
```

`quality` reports current-source intrinsic quality. `overview`, `findings`, `inspect`, and `next` use the selected immutable run. Function IDs use the `F-` namespace, exact findings use `Q-`, and source-snapshot coverage gaps use `G-`. Run selectors accept `latest`, full UUIDv7 IDs, or unique prefixes of at least eight characters.

Priority scores are deterministic and expose quality, coverage exposure, regression, bonuses, and attention bands. PyJEV is optional fuzzy evidence and is never treated as zero when absent. InferLingo uses package-owned exact rules with `ExactUnifier` and provenance only for derived labels and proof paths. It does not parse source, calculate coverage, or assign numeric priority.

Generated sources are excluded from default analysis when they carry conservative markers such as `Generated by`, `@generated`, or `DO NOT EDIT`. Configure exclusions and policy thresholds in `.ledger/covledger/config.toml`; use `quality --include-generated` for explicit opt-in analysis.

## Design invariants

1. Unknown evidence is never silently treated as covered.
2. Failed test suites remain stored and are visibly failed.
3. A run records the command, Python version, Coverage.py version, source hashes, and measured obligations.
4. Source snapshots belong to the run, so later queries can inspect historical code rather than today's file.
5. Semantic judgments keep their probabilities; thresholding is CovLedger policy, not model truth.
6. JSON is a public contract from the first version.

## MVP limitations

`covledger run` currently accepts these pytest forms:

```bash
covledger run -- pytest ...
covledger run -- python -m pytest ...
```

The suite is executed through the interpreter running CovLedger. That is a deliberate MVP constraint. A later executor layer can preserve arbitrary environment managers and commands.

Coverage collection currently delegates to Coverage.py. The intended learning path is to keep this backend as a differential oracle while adding an owned `sys.monitoring` backend later.
